# PRD到UI原型设计助手

## 目标

把 PRD、需求说明、产品想法或已有原型，转成一套**可评审、可预览、可交接**的 UI 原型材料。

这是一个总控技能。普通用户只需要调用本入口；`skills/` 下的文件是内部路由模块，用于让 Agent 在不同阶段保持稳定执行，不要求用户逐个理解或直接调用。

## 何时使用

适合：

- 有 PRD，希望快速做成评审版原型。
- 有产品想法，需要先拆页面、流程和线框。
- 有低保真或页面描述，需要升级为 UI 方案。
- 有 UI 方案，需要生成可预览 HTML 原型。
- 原型准备进入评审或研发交接，需要 QA 和检查清单。

不适合：

- 要求生产级前端工程、完整后端联调或上线代码。
- 要求像素级还原专业设计稿，但没有提供合法授权和完整设计资产。
- 只是做视觉海报、品牌 logo 或纯图片创作。
- 需要真实埋点、接口、安全、性能或兼容性上线验收。


## 技能触发词

用户出现以下意图或表达时，应优先触发本技能：

### 强触发

- “把 PRD 做成原型”
- “根据需求生成 UI 原型”
- “帮我做一个产品原型”
- “生成可评审的 HTML 原型”
- “把产品想法转成页面设计”
- “根据这段需求拆页面和流程”
- “做一个后台 / H5 / 小程序页面原型”
- “把线框升级成 UI 方案”
- “帮我评审这个原型 / 页面方案”
- “整理前端交接清单”

### 弱触发

用户没有直接说“原型”，但出现以下组合，也可以触发：

- 有产品需求 + 想看页面效果
- 有功能列表 + 想拆页面
- 有业务流程 + 想做界面
- 有页面描述 + 想生成 HTML 预览
- 有已有页面 / 截图 / 原型 + 想优化体验

### 不触发

以下场景不要触发本技能：

- 只是写 PRD，不需要页面、原型或 UI 方案。
- 只是做视觉海报、Logo、插画或品牌图。
- 只是写生产级前端代码或修工程 bug。
- 只是做数据分析、竞品研究或商业方案，没有原型交付要求。
- 用户明确要求使用其他专门技能。


## 用户怎么提问

最推荐：

```text
请根据下面这段 PRD，生成一个可评审的 UI 原型。默认桌面 Web，输出页面地图、核心页面、关键交互、可预览 HTML 原型和验收清单。

【PRD】
...
```

也可以：

```text
我想做一个客户运营后台，目标用户是销售经理。核心功能包括客户列表、客户详情、跟进记录和任务提醒。请帮我拆页面、做原型方案，并给前端交接清单。
```

更多模板见 `references/quick-start.md`。

## 总控路由

按用户输入成熟度自动选择路径：

1. **需求不清楚** → 先追问目标用户、端类型、页面范围、交付物。
2. **有 PRD / 需求** → 进入 `01-requirement-to-flow`。
3. **已有流程，需要页面骨架** → 进入 `02-flow-to-wireframe`。
4. **已有线框，需要 UI 方案** → 进入 `03-wireframe-to-ui`。
5. **多页面需要一致性** → 进入 `04-ui-to-design-system`。
6. **需要可预览原型** → 进入 `05-ui-to-prototype`。
7. **准备评审或交接** → 进入 `06-prototype-review`。

## 默认交付物

用户没有特别指定时，默认输出：

1. 输入理解与默认假设
2. 页面地图
3. 用户主流程
4. 核心页面结构
5. 关键交互与状态
6. UI/组件/设计系统建议
7. 可预览 HTML 原型或实现说明
8. 前端交接清单
9. 评审 QA 清单
10. 风险与下一步

## 缺信息时如何处理

只追问会影响方向的最小必要问题：

- 目标用户是谁？
- 面向哪一端：PC / H5 / 小程序 / App WebView / 多端？
- 这次要覆盖哪些核心页面或主流程？
- 希望输出线框、UI 方案、HTML 原型，还是前端交接材料？

如果用户要求快速推进，采用默认假设：

- 后台/管理系统默认桌面 Web。
- 活动/表单/个人中心默认移动端优先。
- 视觉默认简洁、现代、清晰、易评审。
- 先覆盖主流程和核心页面，不强行补全全量系统。

## 输出质量门禁

每次交付前自检：

- 目标是否清楚？
- 页面和流程是否完整覆盖主任务？
- 是否说明关键状态：初始、加载、空、成功、失败、禁用？
- 是否说明交互反馈和异常路径？
- 如果输出 HTML，是否能保存为单文件直接打开？
- 是否明确这是评审级原型，不是生产级代码？
- 是否给出前端交接和下一步建议？

完整 QA 见 `references/qa-checklist.md`。

## 固定边界提醒

本技能包产出的代码、原型和交接说明用于产品、设计、研发评审和沟通，不代表生产级前端代码。若用于真实上线，需要研发基于项目技术栈、组件库、接口规范、安全要求、性能要求和浏览器兼容标准进行重构、测试和验收。
